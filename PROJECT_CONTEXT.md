# MAW — Multi-Agent Workflow (DOCKER-MAW)

## Project Vision

MAW is an agentic framework that automates end-to-end reproduction of scientific workflows
described in published research papers. Given a PDF paper as input, the system reads and
understands the science use case, creates a reproduction plan, generates a containerized
environment, writes the workflow code, and executes it inside that container.

The current science use case is water crystallization nucleation simulation from:
- Yildiz & Peterka (RAPIDS/Argonne): "Agentic Scientific Workflows" — ReAct agent
  reproducing a LAMMPS molecular dynamics + OVITO diamond structure detection workflow
- Yildiz et al. (CISE): "Heterogeneous Hierarchical Workflow Composition" — PyCOMPSs + Decaf

The system runs against the Argonne Argo API (OpenAI-compatible) using Claude Opus 4.6
as the main orchestrator model and Claude Sonnet 4.6 as the coder LLM.

## Agent Pipeline

All agents live in `agent.py` as LangGraph nodes. The edges between the sub-agents and the orchestrator are configured with a conditional edge. The general graph flow is shown below, however the orchestrator has the autonomy to re-direct the flow for situational needs. The soft flow is:

```
orchestrator --> planner    --> orchestrator
             --> installer  (phase 1: generate Dockerfile | phase 2: docker build)
             --> codegen    (generates workflow.py + run_workflow.sh into builds/)
             --> executor   (runs workflow.py inside the sandbox Docker container)
             --> END
```

The orchestrator routes between agents, reviews outputs, and loops agents back
with specific feedback for revision using the Reason, Act, and Observe framework. Each agent tracks a revision counter in AgentState.

## Code Ownership Rules for the AI Assistant

These rules are non-negotiable and must be applied on every response.

1. Before editing any section of agent.py, identify its owner from the tables above.

2. If a requested change touches Ivy's section (codegen, executor, CoderOutput,
   CodeFile, CODEGEN_PROMPT, EXECUTOR_PROMPT), issue this warning BEFORE doing anything:

   *** OWNERSHIP WARNING — IVY'S DOMAIN ***
   The code you asked me to change is in Ivy's section of agent.py: [name the specific
   function/prompt/schema]. This risks overwriting logic she implemented independently.
   Please confirm with Ivy before I apply this change.
   Do you want to continue anyway, or should I suggest an approach that avoids her code?

3. If a requested change touches Jacob's section and Ivy is the one asking, issue the
   equivalent warning with Jacob's name.

4. AgentState is SHARED. Any addition, removal, or rename of a field affects all five
   agents across both domains. Always flag it:

   *** SHARED STATE WARNING ***
   AgentState is used by all agents in both domains.
   Changing field [name] may affect [Jacob's / Ivy's] agents.
   Confirm both teammates are aware before applying.

5. Never silently refactor, clean up, or rename any prompt, node function, or schema
   you were not explicitly asked to change — even if it looks wrong or incomplete.
   EXECUTOR_PROMPT = "TODO" is intentional placeholder — do not fill it in unless Ivy asks.

6. Never remove fields from a Pydantic schema or AgentState without confirmation.
   Fields that look unused locally may be consumed by another agent downstream.

## Stack & Key Conventions

- Language: Python 3.11
- Agent framework: LangGraph (StateGraph with conditional edges)
- LLM backend: Argonne Argo API (OpenAI-compatible endpoint)
  - Orchestrator/planner/installer: claudesonnet46 (Claude Sonnet 4.6)
  - Codegen/executor: claudesonnet46 (Claude Sonnet 4.6), falls back to MODEL_NAME
  - Base URL: https://apps-dev.inside.anl.gov/argoapi/v1
  - Config via: .env (OPENAI_API_KEY, OPENAI_BASE_URL, MODEL_NAME, CODER_MODEL_NAME)
- Sandbox: Docker container built from builds/Dockerfile 
- Console output: rich (Panel, color-coded per agent)
- JSON parsing: _invoke_structured() helper -- tolerates preamble before JSON block

Prompt conventions:
- No em dashes in any prompt strings -- use plain dashes or colons
- Prefer XML tags for structured instructions in prompts
- Each prompt ends with a "HANDLING ORCHESTRATOR FEEDBACK" section -- always preserve this
- All prompts instruct agents to return ONLY valid JSON, no markdown fences

Path conventions:
- All generated files go to builds/ (relative to agent.py location)
- HOST_REPO_PATH env var controls Docker bind mount path (defaults to agent.py directory)
- Inside any container, repo root is always mounted at /app
- Never use $(pwd) in generated shell scripts -- always resolve via ${BASH_SOURCE[0]}
- Inside sandbox containers: LAMMPS data at /app/data/, output to /app/work/run0/

## Running the System

# Via Docker (gives agent access to docker CLI for sandbox builds)
docker build -t maw-agent .
docker run --rm -it \
  -v /var/run/docker.sock:/var/run/docker.sock \
  -v $(pwd):/app \
  -e HOST_REPO_PATH=$(pwd) \
  maw-agent
